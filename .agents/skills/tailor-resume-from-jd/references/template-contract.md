# 初始简历版式合同

## 不可变基准

初始简历是视觉真值来源。默认保持以下项目不变：

- A4 页面尺寸、纵向方向、单页布局和页面边距
- 单栏或双栏结构及各栏宽度
- 表头内容、顺序、对齐、图标、技能标签和装饰元素
- 栏目名称、栏目标题方块、分隔线和颜色
- 字体文件、字体栈、字号、字重、行高和字距
- 标题、单位、职位、日期、正文、标签和强调文字的样式
- 区块、条目和列表之间的间距规则
- 原模板用于强调关键词的 HTML 标签和 CSS 类

“保持模板”不是视觉上大致相似，而是复用同一结构和样式规则。若源代码可用，优先直接引用原样式；必须复制到独立产物时保持样式文件逐字节一致并记录校验值，不要凭目测重写。为适配一页，只能增删、合并或改写内容，不得调整 CSS。

## 本示例站点的已知来源

仅当当前仓库是 `zlr930.github.io` 时使用这些路径：

- 主页简历入口：`resume/index.html`
- 主页简历 PDF：`public/resume.pdf`
- 简历组件：`src/resume/ResumeApp.tsx`
- 简历内容：`src/resume/data.ts`
- 简历样式：`src/resume/resume.css`
- 个人主页组件与信息：`src/App.tsx`、`src/data.ts`

默认不得修改上述文件。将岗位定制版放在 `deliverables/`，并确保它不会替换主页的简历链接或 `public/resume.pdf`。

当前模板的已识别样式参数、结构和加粗实现记录在 [current-template-profile.md](current-template-profile.md)。该档案用于快速核对，不取代仓库中的最新源文件。

## 内容事实边界

事实可以来自初始简历、个人主页、用户在对话中补充的内容或用户提供的可靠材料。改写时允许：

- 调整表达顺序，使岗位相关动作更靠前
- 使用 JD 中的标准业务术语描述来源中已经存在的同义事实
- 合并重复项目或同类个人实践
- 删除低相关内容，给高相关经历更多空间
- 将量化数据和结果前置

改写时禁止：

- 捏造职责、项目、工具、证书、成果、排名或数字
- 把“协助”“接触”“了解”升级为“负责”“主导”“精通”
- 因 JD 提到某流程，就假定用户做过该流程
- 添加无法由来源支撑的性格判断或能力结论
- 为填满页面重复同义内容

## 加粗规则

先识别初始简历中加粗的语义和实现方式，再沿用。通常遵循：

- 单位、项目名称、职位或关键身份按原模板固定字重显示。
- 正文只强调与 JD 直接对应、且有事实支撑的短语。
- 优先强调业务动作、方法、工具、关键协作、量化结果和最终产出。
- 单个强调短语宜短，不要把整条列表项全部加粗。
- 同一条中连续强调不宜过多，避免页面变成斑驳的粗体块。
- 若模板使用 `.detail-emphasis`、`strong` 或特定组件，候选简历使用相同实现，不新建近似样式。

## 字体与排版比对

浏览器环境下至少比较这些计算样式：

- `font-family`
- `font-size`
- `font-weight`
- `font-style`
- `line-height`
- `letter-spacing`

对基准与候选中共同存在的代表性元素逐项比较，包括页面、表头、姓名、联系方式、技能标签、栏目标题、条目标题、职位、日期、正文、固定粗体和正文强调。同时比较这些元素的边距、内边距、布局、间距、颜色和边框等计算样式，避免出现“字体相同但版式已变”的伪一致。

字体文件须等待 `document.fonts.ready`。计算样式中的 `font-family` 只代表 CSS 声明，不能证明实际字形来源；同时使用浏览器平台字体接口核对真实字体。若使用网页字体，确认请求成功且没有退回文泉驿、DejaVu 等系统替代字体。候选与基准的表头在未授权修改时应满足：

1. 规范化文本完全相同。
2. 表头截图像素完全相同。
3. 代表元素的计算字体属性无差异。

## 单页和填充标准

候选简历必须同时满足：

- DOM 中恰好一个打印页容器。
- 页面内容没有横向或纵向溢出。
- PDF 恰好一页。
- 文本、图标和装饰元素没有遮挡或截断。
- 最后一项内容与页面底边之间保留安全空间，同时视觉上接近初始简历的填充程度。

默认验证器允许正文内容底部距页面底边 `20–90px`。这不是通用设计常数：若初始模板的真实安全边距不在此范围，应先测量基准，再通过 `--min-bottom-px` 和 `--max-bottom-px` 传入相近范围。不要以零底边作为“铺满”的标准。

## 推荐验收顺序

1. 确认候选文件独立，基准文件无改动。
2. 运行仓库构建、类型检查和 lint。
3. 启动本地服务器，确保基准和候选使用同一浏览器环境。
4. 运行 `validate_resume.mjs` 并导出 PDF/截图。
5. 用 `pdfinfo` 或 `file` 确认页数。
6. 将 PDF 第一页渲染成位图，目检表头、正文密度、底部边距、强调和重叠。
7. 检查最终文件名、中文字符、链接和联系方式。
